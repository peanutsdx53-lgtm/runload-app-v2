# RunLoad v2 記録系UI承認仕様・実装引継ぎ（2026-10-24）

## 対象・境界
- 対象は `peanutsdx53-lgtm/runload-app-v2` のみ。旧 `runload-app` main/Current/科学計算ロジック・保存契約は変更しない。
- デザイン参照: ライブラリ `RunLoad_Screen_Design_Repository/11...選択` と `15_RunLoad_v2_手入力とコース設定_Ver2_20261024.md`、画像・HTMLは `RunLoad_v2_Record_Course_Design_v2_20261024.zip`。
- ホームで確定した濃紺/青緑と立体カード、簡潔な見出し、ナビゲーション重複禁止に準拠。
- ユーザー承認: スマホ「記録」→ GPS/手入力選択、PC「記録」→手入力直行。手入力は距離kmと総時間(分・小数可)横並び、記録種別、日付、詳細の入口のみ。コースは坂道と路面の種類・割合・最大5区間を維持。

## 今回の画面・操作
- `#/record-start`: スマートフォン向けGPS/手入力カード（PCナビは直接手入力）。GPS測定エンジン未接続の旨を明示。
- `#/record`: 走行/休養、日付、距離、総時間(分)、任意情報の入口、入力確認。ペースは入力が揃った場合の単純な距離・時間計算であり、科学モデル結果ではない。
- `#/record-course`: コース名、坂道の不明/平坦/割合/区間、上り・下り・平坦を同じ列に表示。割合の合計超過を防ぎ、未入力を0と扱わない。路面8種類の1種類/複数・割合タップ選択、割合100%確認。区間は最大5、割合/方向/傾斜/路面を入力。値を保ったまま前画面へ戻れる。
- `#/record-rof`: 著者確認済みROF-Jの0〜10・画像資料を既存実装から継承。運動前後を個別入力し、未入力と0を区別。
- `#/record-more`: 旧v2の歩数・測定元、走歩混在、気温・環境メモ、身体の気づき・シューズ名・自由メモを保持。将来専用派生画面化可能。

## 主な変更ファイル
- `app.js`: 記録関連ルーティング、入力編集、旧フィールド維持、レビュー確認、ナビの強調。
- `ui/recordExperience.js`: 承認デザインの表示・サマリー・入力モードと確定条件。
- `ui/recordExperience.css`: 記録系画面だけに作用する暗色デザイン・レスポンシブ。
- `ui/recordDraftReview.js`: 手入力の `minutes` を時内の0–59から**総時間(分)**0–100000に拡張。旧時・秒フィールドは削除しない。
- `index.html`, `sw.js`: CSS/JS読込、PWAキャッシュ更新。
- `tests/recordExperience.test.mjs`, `tests/browserSmoke.mjs`: 操作・欠測・表示幅・値保持・ROFと旧入力欄の退行検証。

## 保存・計算の重要な制約
- **このUI改修だけでは正式な記録保存、GPS測定、科学エンジン、コースライブラリの接続は完了しない**。記録確認ボタンで保存完了を装わない。
- UI状態は現在開いているSPAセッション内に保持。リロードをまたぐ正式な下書き保存はまだない。
- 坂道割合は上り・下り両方の入力があるときに限り平坦割合を算出する。区間入力の負荷モデル適用はしない。
- 路面の選択状態と非アクティブモードの入力値は編集セッションでは保つ。**将来正式保存へ接続するときは選択中モードのデータだけをシリアライズし、旧版保存契約に適合させる必要がある**。
- 旧v2入力の `minutes` は総時間(分)へ意味が変わった。旧版の `hours`/`seconds` と正式統合する際は明示変換が必要。既存の科学計算入力を無検証で入れ替えない。
- 複数端末で操作できるUIだが、ブラウザ間のデータ同期は未実装。
