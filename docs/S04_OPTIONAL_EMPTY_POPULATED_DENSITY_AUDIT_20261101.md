# RunLoad v2｜手入力・任意画面：空欄／多項目入力の実画面監査（2026-11-01）

## 目的と制約
対象はS04手入力、S05相当の5つの別経路「コース・走行条件」「運動前後の疲労感」「歩数・走り方」「環境」「身体・使用品・メモ」。主目的は、研究上必要な区別を保ちつつ、重複する常設説明と、入力情報量の増加で生じる視覚・操作上の問題を抽出すること。本監査はテストのみを追加し、ユーザー向け本体の画面、正式Current、科学式、保存スキーマを変更していない。

GitHub Actions `Record optional screen density audit` run `41276409208`、ChromiumとWebKitの両方でSUCCESS。各320/390/1440pxで全5任意画面の未入力状態と入力状態を撮影。試験用の事実は以下であり、ユーザー本人の実データ／効果の実証ではない。

- ROF-J：運動前4、運動後8、本人申告の運動時刻08:45–09:39。
- 歩数・走り方：12,457歩、概数入力、走行＋歩行、走行部分6.12km／38分。
- 環境：気温18.5℃、本人入力の長文メモ約312文字＋天候・風の明示反映。

## 優先度別の発見

### P0：身体・使用品・メモ
**画面設計根拠**：12個の選択チップ、部位名ピッカー、3つの独立した入力カード、別途部位名転記カード、注意文、フッターを縦方向に積む。390pxで選択部位12件＋448字メモを入力した実画面は、未入力時のコンパクトさから大きく乖離する。テキスト欄は高さがほぼ固定で、390pxにおける本文448文字のtextareaは `clientHeight / scrollHeight` で約11%（Chromium/WebKitとも）の高さしか一度に表示されない。身体自覚情報240字も約19%。長文を読む・修正する際に欄内スクロールとページスクロールを行き来する。
**機能上の境界**：人体図の選択は `bodyUi.selected` の一時状態であり、保存対象は `bodyObservation`、`shoeName`、`memo` の既存3キーのみ。選択を自覚情報へ反映する明示操作は安易に撤去しない。身体部位選択は医学的診断・12部位参考値を計測した結果ではない。
**確認した不具合**：`bodyContextExperience.js` のシューズ名入力上限は `maxlength=100`、初回表示カウンターは `/100`。対して `app.js` の入力イベント中は `shoeName?120:500` としてカウンターを更新する。入力中と再描画後で上限表示が異なる。この不整合は画面の高優先修正対象。
**廃止候補**：ヘッダーの副題「身体で感じたことと、使ったもの」、入力列の「必要な項目だけ入力してください」、部位名追記カードの上下一致する説明2本、複数箇所の「選択は診断ではない／参考値を算出しない」という同旨の常設文。
**改善案**：選択中の部位は件数と最近の数件を常時表示し、「すべて表示」で12件を確認・解除できる可逆的な表示。全件の選択は内部で保持する。メモ欄は入力に応じて高さを伸ばす（例：最大6〜8行、その後は欄内スクロール）、入力中の文字数上限を統一。本人の自覚情報と身体部位の文献参考値の違いは、見出し下の1文または「説明」内に一本化。部位の追加・解除・選択名の文章化は保持する。正式な部位タグ保存を新設するなら別の保存契約・承認が必要。

### P1：環境
**事実**：気温と環境メモは既存のドラフトキーだが、天候・風・湿度は一時的なUI状態。利用者が「環境メモに反映」した内容のみ、既存の文章として保存対象になる。入力済み状態では約312字が固定高さのメモ欄に入り、390pxで `clientHeight / scrollHeight` 約17〜18%の表示。反映後も文量は増え、約335文字となる。
**廃止候補**：「覚えている範囲で」「0℃と未入力は別」「もう一度押すと解除」「一時表示です」「自動で書き換えない」「下の操作で追記」「下部でも反映を押したものだけ保存」といった説明の常設重複。
**改善案**：保存の区別は削除しない。天候チップの直近に `未反映／環境メモに反映済み` を明瞭な短い状態ラベルとして示す。反映操作の前後で画面を比較できること。気温の欠測と0℃の違いは説明の反復より入力UIと確認時の値で明示。環境メモの縦方向表示も長文対応。

### P1：コース・走行条件
**事実**：5区間と複数路面の組合せでは、320／390pxでページがかなり長くなる。ただし5区間までの追加・入力、割合100%の確定、今回の記録への適用と次回用コース保存の2操作は意図された異なる機能で、統合・無条件削除はできない。
**廃止候補**：「必要な条件だけ」「保存済み・新規」「使わない場合は次へ」「保存コースなしの説明」「コース名は識別用」「わからない項目は不明」「区間の使い方」「区間割合は100%」「適用は保存を更新しない」「コースを保存すると次回に使う」「保存・削除は過去記録に影響しない」のうち同旨が複数箇所にあるもの。
**改善案**：空のときは不明モードの説明を簡潔にし、区間モードでは「区間1〜5」の要約と編集展開を用いる。未編集区間の入力値を非表示にする場合も現在の設定は保持。今回の記録へ適用と、保存コースを新規作成／更新する操作の違いは明示。100%と欠測・区間の制約は実際の入力検証として残す。

### P1：ROF-J（運動前後の疲労感）
**事実**：未入力の状態と4／8を入力した状態の両方を撮影。スコア0と未入力は異なる。尺度0〜10の11段階・5代表イラスト・出典表示を保持する必要がある。本人申告の開始／終了時刻とROF-J回答時点は別の情報。
**廃止候補**：操作方法「横軸で選択」「イラストは説明用」「中間値は入力できない」、体験上の限界「医学的な判断ではない」「部位別の値ではない」の常時表示が重なっている部分。
**改善案**：数値選択と意味の短い説明を第一面に残し、尺度の詳説・補足・出典を必要時の展開へ整理。運動時刻と本人による回答時点は現行の折り畳み構造を維持し、時刻は基本情報の日付を再入力させない。出典情報と著作権表記は消去しない。

### P2：歩数・走り方
**事実**：活動種別の重複は前回解消済み。歩数と取得方法は別物。走行＋歩行の場合は部分距離・時間を追加し、走歩混在の単一活動12部位参考値は算出しない。
**廃止候補**：「必要な情報だけ」「端末計測／概数入力の長い言い換え」「走った部分を記録」「走歩混在を算出しない」の文と動的警告の反復、「確認画面に引き継ぐ」の繰り返し。
**改善案**：通常時は歩数・取得元・走行パターンのみ。走歩混在を選んだ場合に限り区間入力と具体的な制約を開き、説明・警告は一箇所にまとめる。GPSが歩数を推定しない事実、残差が実測歩行距離ではない区別は意味を変えず短く残す。

### P2：手入力の基本画面
**事実**：必須説明ボックスと個別必須バッジは前回削除済み。現行は基本情報「必須」、必要項目の動的入力状態、追加情報「任意」と5つの別経路。入力済み時のカード要約は例えば「身体・使用品・メモ：入力あり」に留まり、内容が多いか、どの種類の記述かは区別できない。
**廃止候補**：入力済み直後にまで出る「必須3項目が入力済み」、記録確認ボタン直下で繰り返す科学参考値の長文。入力不足の警告自体は保存前検証を残す。
**改善案**：未入力時は過剰警告を見せず、保存確認の試行時や必要な位置で不足理由を出す。5つの任意画面の戻り表示は「気温あり」「自覚情報あり・シューズあり・メモあり」など事実に基づく簡潔な要約。原文のセンシティブな記述をホーム的なサマリーへ無断表示しない。
