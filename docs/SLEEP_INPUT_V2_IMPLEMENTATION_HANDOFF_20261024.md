## 対象と承認内容
対象は `peanutsdx53-lgtm/runload-app-v2` のホーム > コンディション。旧 `runload-app` は変更していない。
ユーザー承認：時刻からの入力（就寝・起床）を基本に、合計時間だけの入力も残す。前日／当日の切替は通常非表示・自動判定。入力欄の外観はホームと記録画面の濃紺・青緑。iPhone/Android/PCで機能と記録形式を統一する。

- `tests/browserSmoke.mjs`: 320/390/430/1440pxで時刻欄の収まり、24時間表記、モード切替、6時間40分の計算、エラー表示、保存・再読込・旧データの操作確認。

## データ互換性
保存先は変更せず `localStorage["runload-v2-life-condition-v1"]` を継続利用。最大366日。記録日 `date` は**起床した日**として扱う。

従来の保存形は維持（例）：`{date:"2026-10-24",sleepMinutes:400,feeling:"ふつう",memo:""}`。この既存オブジェクトに就寝時刻や起床時刻を推測補完しない。

新しい時刻入力：`{date,sleepMinutes:400,feeling,memo,sleepSource:"clock",bedTime:"23:20",wakeTime:"06:00",bedDayOffset:1,bedDayRule:"auto"}`
新しい合計のみ：`{date,sleepMinutes:450,feeling,memo,sleepSource:"duration"}`

`clock` の `sleepMinutes` は就寝と起床の**時計時刻の差に基づく就床経過**であり、実測した睡眠時間ではない。`duration` は自己申告の睡眠時間。`sleepSource` がないものは旧版の値として保存し続ける。前日自動判定は就寝時刻が起床時刻より遅い場合。0分、24時間以上、無効な日付関係は保存しない。既存の科学計算や正式走行エンジンの定義に入力値を転用していない。

## UX上の決定
- モーダルを開くと日付と時刻入力が最初に見える。7日の記録推移はフォーム下に配置（削除はしていない）。
- 入力欄の表示は一律24時間表記（例 23:20 / 06:00）。内部入力は各OSの標準 `type=time` を利用し、画面の表記のみ共通化する。
- 初めての時刻入力では時刻を勝手に初期入力しない。既存の時間のみの記録は「合計時間だけ」で開く。
- 入力の組み合わせが矛盾する場合はフォーム内に説明を表示し、画面を再生成せず入力を保護する。
- 詳細で日付を変更した場合、保存済みの該当日の入力を読み直す。日付変更前の未保存編集は維持されないため今後のUX改善候補。
