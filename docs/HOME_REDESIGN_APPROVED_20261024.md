# ホーム再設計・承認仕様と実装引継ぎ（2026-10-24）

作業対象：この `runload-app-v2`。旧 `runload-app` の main / Current は変更しない。

## 承認した方針
- ホーム＝自由編集可能なマイダッシュボード。ナビゲーションと重複するボタン、反復的なブランド表記、挨拶文、無意味な飾り見出しは廃止。
- 最新走行／コンディション／実績／ナビ外クイックアクセスを主要領域とする。活動の推移・探究の続きは追加ウィジェット。
- コンディションは生活習慣の観察用。運動前後のROF-Jと区別する。睡眠・起床時の調子と直近7日の入力推移が主役。根拠のない健康・回復総合スコアは作らない。
- 実績は収集・達成型の視覚表現。正式な保存記録・旧実績エンジンとの接続前に架空の達成を事実表示しない。
- iOS/Android/PCで共通利用を優先。HealthKit / Health Connectを必須としない。生活データは任意入力、正式走行記録の自動読み込みは後工程。
- 承認画像：`runload_home_v2_mobile.png`、`runload_home_v2_desktop.png`（画面全体）と、`runload_condition_achievements_populated_v1.png`（コンディション/実績のデータ入り見せ方）。画像中の数値・バッジはすべて参考表示例。

**データキー**：`runload-v2-life-condition-v1`（睡眠分数・起床時状態・メモ・日付、最大366日）。旧記録・科学計算・ROF-J保存は変更しない。ホーム配置キーは従来の `runload-v2-home-dashboard-layout-v1`。既存の保存レイアウトを上書きしない。

**内部互換性**：既存の `topics` ウィジェットIDは**実績カード**のIDとして再利用している。未来のリファクタリングで勝手に変更すると旧ユーザー保存配置が壊れるため、明示的移行が必要。

## 機能制限（必ず伝える）
- **表示例モードの走行、睡眠、バッジ、進捗は架空**。明示的に起動しない限り通常画面に表示しない。正式記録・獲得データには書き込まない。
- 正式なランニング保存データ・実績判定との接続、生活/走行の相関分析、探究ツリーへの自動連動、iOS/Android/PC間の同期は**未実装**。
- 実績は表示例または「未接続」を表示。コンディションの手動入力だけが端末内で動作する。
- 旧RunLoadの科学計算・保存・比較適格性・GPS状態・ROF-Jは触らない。
