# GPX・What-ifシミュレーション：Ver.33実装・検証契約

対象: `ui/gpxImport.js` / `ui/simulationExperience.js` / `ui/simulationExperience.css` / `tests/*`。正式研究Current・Reference-100計算器・保存済み走行・手動コース保存スキーマに**変更を加えない**。

## 1. 利用者の目的

GPSで走っていなくても、GPXファイルからコースの形と、含まれる場合は標高を見られる。利用時間・仮の走行ペース・走歩区間を指定し、A「一定ペース」／B「走る＋歩く」の**算術上の進行距離とコース上の対応位置**を比較する。疲れ方、傷害リスク、実際の到達可能性、12部位の身体負荷を予測しない。

- 手動・保存済みコースはVer.32からそのまま利用可。位置・標高がないため、地図や「コース上の到達地点」は描かない。
- 「コースなし」では時間と距離の仮定だけを比較し、残り距離・到達地点は表示しない。
- GPXは端末内で解析して一時的に使用する。ページ再読み込みで消え、サーバーへ送信せず、端末保存や共有も自動では行わない。
- GPS実走記録の再利用は現行アプリに保存可能な軌跡データ契約がないため未接続。画面上も無効と明示する。

## 2. GPX契約

- `.gpx` のローカルファイル（最大5,000,000バイト）を標準`DOMParser`でXMLとして解析する。`DOCTYPE`と`ENTITY`は受け付けない。外部ライブラリ・外部経路検索・外部標高APIへの通信はない。
- ルート（`rte/rtept`）およびトラック（`trk/trkseg/trkpt`）、GPXの名前、位置点の緯度・経度、任意の標高（`ele`）を扱う。
- トラック区間の途切れは距離に加えない・線を描いてつながない。GPXの位置点間は球面近似の直線距離であり、実際に歩行可能な道路距離とは限らない。
- ファイル中24コースまで、各コース25,000点まで、全体25,000点まで。対象コースの距離は0.1～1,000km。範囲外・欠損・非数・解析不能な座標/標高では**読み込み失敗**とし、既に読み込んだコースを壊さない。
- 標高がゼロの場合は数値0として扱う。標高が欠測の場合は補完しない。標高が全欠損なら標高図を出さず、部分欠損なら欠測部分をつないで描かない。
- 複数コースの場合はユーザーが選択。ファイル名・コース名はHTMLエスケープして表示。
- GPSの位置点だけから背景地図、地形の3Dモデル、舗装・未舗装の種類、道路の通行可否などを捏造しない。SVGの軌跡はあくまで緯度・経度の**概略図**。

## 3. 表示上の区別

- **実際の情報**: GPXで渡された軌跡と標高値、または手動保存コースの坂道・路面情報。
- **算術上の仮定**: A/Bの平均ペース・走る/歩く区間・仮の進行距離。
- **表示できないもの**: 実際の疲れ、GPS未収録の場所、標高欠損、走行の安全、本人の能力と将来の実走位置。

仮の進行距離がGPX長を超えた場合は末端で位置表示を止め、走った先を地図に延長しない。距離・時間の数値は元の保存データに書き戻さない。結果は一時的表示のみ。

## 4. 受入試験

1. Node: 均一ペース・走歩の算術、距離計算・進行点の補間、入力範囲、GPX未選択、XSS・容量制限。
2. Browser DOMParser: 名前空間付きGPX 1.1の実XML、複数区間、標高あり/なし、壊れたXML、DTD/ENTITY、不正座標を拒否。
3. Browser E2E: フォームから実GPXを選択 → 正確な名前・距離 → 軌跡と標高 → A/B切替 → ペースや時間変化 → 不正ファイルからの回復 → 手動とコースなし → 再読み込み後にGPXを保持しない。
4. 320/390/820/1440px: スクリーンショット検査、文字・カードの重なりなし、横スクロールなし。iOSで編集欄の16px以上を維持。
5. GitHub Actions：Node・Chromium・WebKit・Pagesのワークフローを確認。科学的な実測妥当性やiPhone実機テストとは明確に区別。

## 5. GPS実走履歴接続時の条件

次フェーズでは、**軌跡の保存可否を本人が明示的に選べる**独立した契約が必要。生のGPS位置点・標高の出典・区間境界・記録ID・修正履歴・取得精度を定義し、上記の軌跡描画関数が読み取れる正規化形式に変換する。既存の手動走行記録、科学計算、手動コースプリセットにGPS点列を混ぜ込まない。保存量上限、削除・エクスポート、端末共有、プライバシー検証を別途実施する。
