## 睡眠入力：確定した考え方
- iPhoneで実機確認済みの標準ホイール式 `input[type=time]` を排除しない。Androidでは端末の標準時刻ピッカー、PCではキーボードで見える時刻欄を利用する。**機能と保存結果の同等性を優先し、OSのピッカーを無理に同一画像へ統一しない**。
- 電話サイズ（320/390/430px）ではアプリ共通の24時間表示（例 23:20/06:00）と大きな選択領域を持ち、OS標準ピッカーへ連動。大きなPC幅では編集可能なネイティブ欄を表示するため、PC環境の地域設定により AM/PM 表示になる場合がある。内部保存は常に `HH:MM`。
- 「合計時間だけ」モードは `7:30` をキーボード入力する代わりに、**時間と分の2入力欄**、さらに `00分／15分／30分／45分` の1タップ選択を用意した。任意の分（1分単位）は直接入力できる。入力値が片方だけの場合や範囲外の場合は保存拒否。
- 保存フォーマット・キー `runload-v2-life-condition-v1` は据え置き。`clock` は就寝〜起床の就床経過、`duration` は本人申告の睡眠時間。古い記録を変換せず、就寝・起床時刻を推測しない。
- 改修ファイル：`ui/homeExperience.js`, `ui/homeExperience.css`, `app.js`, `tests/homeExperience.test.mjs`, `tests/browserSmoke.mjs`。
- 検証：GitHub Actions `UI Next smoke`、`UI browser visual smoke`、Pages公開の最終変更コミットですべてPASS。ブラウザーでPC 1440、モバイル幅 320/390/430 の見た目・保存・再読込・分チップ選択を確認。
- 未検証：**今回の最終版のAndroid実機操作、iPhone Safari実機再検証、VoiceOver/TalkBack**。Chromiumのスマホ「幅」検証は実機同等ではない。依然として正式な健康連携・端末間同期は未実装。

## 次画面の設計案：GPS測定 Ver.2（未承認・未実装）
設計プレビュー：`runload_gps_concept_v2.html`。切替可能な4状態とPNGを同梱。PCはナビゲーションから手入力へ直行する既存方針を維持し、GPS測定はスマホ専用として検討する。

1. **準備**：GPS状態・権限が未確認の間は「測定開始」を無効化。計時0、距離・ペースは未測定として `—`。未接続を明示。
2. **測定中**：時間を最大表示、距離・平均ペースを同格で表示、GPS状態を常時示す。架空のGPS地図・走行軌跡は描かない。走行中は下部ナビゲーションを隠して誤移動を減らす案。
3. **一時停止**：計時・距離は固定し、「再開／終了」を分ける。測位を失ったときの中断・再開条件はエンジン実装前に確認する。
4. **終了確認**：誤終了防止の確認ダイアログ。戻ると元の状態に戻る。実際にはここから共通の記録確認・追加情報入力へ移るべきだが、この設計試作ではまだ正式保存と接続していない。

デザイン：ホーム・記録と共通の濃紺・青緑カード、大きく読みやすい数値、44px以上のタップ領域を狙う。サンプル値は必ず「表示例」と明示し、GPSエンジンを動かしていると誤認させない。
