# UX-023｜保存済み走行の学習カード：実画像と出所の受入

作成日：2026-11-02。対象 S12 探究・学習カード。最終判定：**実画面再撮影・最新P0再検証待ち（未PASS）**。

## 1. 根拠・発見

- **機能設計根拠**：学習は一般的な説明と本人の記録を区別する。保存した手入力走行の平均ペースは、本人が保存した距離と経過時間から算術計算した値であり、原因・疲労・身体負荷の診断ではない。未保存エディタの入力と保存済み走行を混同しない。特定の保存済みIDへの導線は別の最新IDで代用しない。
- **画面設計根拠**：学習カードの見出しに「最新の保存済み走行（手入力）」と表示しつつ、下段の「あなたの記録とのつながり」欄が「関連する入力がなくても、内容を自由に学べます」となり、出所が矛盾する。ユーザーが保存・選択した記録と、入力途中・表示例・生活記録を視覚的にも区別する必要がある。
- **修正前の目視証拠**：[UI browser visual smoke 41321520237](https://github.com/peanutsdx53-lgtm/runload-app-v2/actions/runs/41321520237) (SHA `7de55a95`) `runload-ui-next-screenshots/mobile-pace-card-saved-v28.png`。実際の390pxカードで上記矛盾を確認。
- **実ブラウザの反例から追加発見**：[UI browser visual smoke 41322628378](https://github.com/peanutsdx53-lgtm/runload-app-v2/actions/runs/41322628378) と [P0二件保存 41323028902](https://github.com/peanutsdx53-lgtm/runload-app-v2/actions/runs/41323028902) で、保存後もエディタの一時入力が残ると、「最新の保存済み走行」と計算値が表示される一方、関連欄が「入力中の走行距離・時間などに関連」と表示されることを検出。正常なCI PASSではなく**受入失敗**であり、記録した。

## 2. 修正内容

- `ui/explorationExperience.js`：保存済みの有効な手入力走行を実際に学習カードの計算に使うなら、出所の説明も**同一の保存済み走行**に揃える。入力途中の値が別途存在する場合は「この学習カードの計算に用いていません」と明示。保存済みが無い場合は、入力途中・未入力・読み取りエラー・表示例を区別し、偽の保存済み走行を作らない。
- `tests/explorationLearning.test.mjs`：未入力／未保存途中／保存済み1件・2件／別IDでの選択／存在しないID／保存済みと入力途中が同時に存在する反例を追加。
- `tests/browserSmoke.mjs`：実際に保存した走行を表示したカードに、その走行の出所が説明され、「関連なし」と誤記されていないことを検証。320/390/1440等のスクリーンショットを既存経路で保存。
- `tests/twoRunCycleBrowserSmoke.mjs`：実際に**別々に保存した2件**の最新・選択記録について、390pxと1440pxの学習カードを撮影し、異なる記録IDと日付を取り違えないことを検査。
- `app.js`・`index.html`・`sw.js`：PWAのJSキャッシュ版を更新。既存保存データや科学計算式・12部位・結果の3タブは変更しない。

## 4. 目視と反例の追跡結果（2026-11-02追記）

- **最新・選択記録の実画像を目視確認**：[P0 run 41323216933](https://github.com/peanutsdx53-lgtm/runload-app-v2/actions/runs/41323216933) の Chromium（同一実装のSHA `3840fab9`）では2回の再実行が成功。`chromium-UX023-two-saved-latest-390.png` は2026-10-21/5.00km、`chromium-UX023-two-saved-selected-390.png` と `-1440.png` は2026-10-19/4.00kmを表示。「あなたの記録とのつながり」も各日付の保存済み走行を示す。画面を実際に開き、主要文字の切れ・横はみ出しがないことを確認。
- **撮影方法の追加発見**：固定モバイルナビがカードの要素スクリーンショットの中央に写り、下部記述の目視を妨げる。このまま「レイアウト不具合」と誤判定せず、実際のビューポート画像と、撮影中だけナビを自然フローに移して全カードを確認する監査用画像を**別々に保存**するよう `tests/twoRunCycleBrowserSmoke.mjs` を修正。アプリ内の固定ナビ位置や操作を変えない。
- **WebKit の再生競合**：同じrunのWebKitはテスト失敗。選択IDへURLを切り替えた瞬間、以前の「最新」カードがDOMに残っており、単純な「カード要素が存在する」待機では間違う。選択した走行のラベルと日付が描画されるまで待機してから画像・文字を検査するよう修正（`d5fa0b43`）。失敗をUIの合格証拠として使わない。
- **正常／反例の切り分け**：空の学習／入力途中／保存済み1件／保存済み2件／保存済み+旧エディタ未保存／特定ID・欠損IDを単体テストで区別。特に「保存済み+未保存」は実ブラウザの失敗から得た回帰条件であり、保存済み計算と画面上の出所説明が一致するよう修正。
- **この追記時点**：新たなP0 WebKit/Chromiumの同一SHA再撮影が終わるまでは、UX-023を最終PASSとはしない。

なお正式Current・科学式・3タブは非変更。実機iPhone/Androidは別ゲート。
