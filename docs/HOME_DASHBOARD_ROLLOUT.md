# RunLoad v2 — ホーム自由編集の段階的移植と付属画面ロードマップ

基準：2026-10-23。対象は作業用 `runload-app-v2`。旧 `runload-app` の Current/`main` と保存記録・科学計算には変更を加えない。

## 旧版の実装を確認した内容

既存ソース：
- `ui/mobileHomeDefaultLayout.js`：ホームのウィジェット初期配置（today / plan / changes / checkpoint）、ウィジェットの大小、表示・非表示
- `ui/interactions/mobileHomeGridModel.js`：4列配置、サイズ別の占有セル、空き位置の探索
- `ui/mobileHomeWidgetIconSwap.js`、`ui/interactions/mobileHomeInteractions.js`：編集操作・配置変更
- `ui/mobileHomeHub.js`：複数ページへの移動
- `ui/mobileHomeGridUtilities.js`：旧版保存設定の**既存バイトを壊さない**書き込みゲート
- `screens/mobile/achievementsScreen.js`、`ui/mobileAchievements.js`：保存された記録をもとに実績の進捗を表示
- `screens/mobile/runMeasurementScreen.js`、`ui/mobileRunMeasurementInteractions.js`、`ui/runMeasurementCore.js`：実GPS測定・状態・ROF-J連携

## v2ホームの移植工程

| 工程 | 実装範囲 | 検証・完了条件 |
|---|---|---|
| **H1 今回** | 6カードの表示・非表示、上下移動、横幅変更、キャンセル／初期化／端末内への保存 | 320 / 390 / 430 / 1440px幅で表示・編集テスト。旧版3キーを変更しない。保存失敗や破損データは上書きしない |
| **H2 今回：一部実装** | 専用ハンドルを長押ししてカード順をドラッグ移動。移動先の挿入ライン、ドラッグ中の縁スクロール、ポインター取消／キャンセル対応を追加。上下ボタンは引き続き利用可能 | Chromiumの320/390/430px・PCでドラッグと保存を検証。**実機Safari/Androidと旧版同等のウィジェット選択UIは未達** |
| H3 次工程 | 複数ページ、ドック/アイコン配置、ウィジェットサイズ・配置グリッドの完全版 | 旧版のレイアウト意味論との対応表を完成し、操作/復元・狭幅を検証 |
| H4 承認後 | 実データ・保存設定の継承、同期・バックアップ等 | 旧版との互換性と破損防止の監査を通した後に実施。ユーザーデータは自動移行しない |

H1の保存先は **`runload-v2-home-dashboard-layout-v1`**。旧版の
`running-record-mobile-home-layout-v1`、
`running-record-mobile-home-positions-v1`、
`running-record-mobile-home-widgets-v1`
には一切書き込まない。設定はブラウザ/端末内の表示用設定のみで、ユーザーの走行記録や科学計算値は保存しない。これをもって旧版の「自由編集機能の完全移植」とは呼ばない。

## H2ドラッグ操作の範囲と留意点

- 編集中のみ、各カード上部の移動ハンドル（⠿）を長押しして移動します。マウス操作ではハンドルを押したまま移動します。
- ハンドル以外のカード部分にドラッグ処理を掛けず、記録ボタン・テーマなどの通常操作と競合させません。
- 先頭／末尾の配置は移動先のカード上半分／下半分で決定します。挿入ラインで視覚的に示します。
- 指を離した時点では**編集中の表示順**だけが変化します。保存ボタンを押すまで永続化しません。
- 操作取り消し、ポインター取消、編集キャンセル、画面離脱時には操作中の状態を破棄します。
- スマホの端末やブラウザによって、長押しやスクロールとの優先順位が変わる場合があります。実機確認・微調整を残します。正式な4列グリッドの占有セル処理、ページ・ドック操作は**未実装**です。

## 実績（Achievements）

- **画面デザイン**：総達成件数、次の目標、進行中、達成済み、未着手のグループ。実績の表示のみのモックアップ段階では架空の「達成済み」を描かない。
- **判定データ**：必ず正式な保存記録に基づく `syncAchievements` の仕様を確認。距離・回数・時間・活動種別、必要な場合はエネルギー推定の根拠と欠測の扱いを再検証。
- **実装順**：視覚仕様の確認 → 現行画面へ構造を移植 → 既存実績データとの契約照合 → 実機・保存テスト。
- 正式な記録・実績エンジンが接続されるまでは、実績を「獲得済み」と誤表示しない。

## 測定（GPS Measurement）

- **画面デザイン**：GPS品質、走行時間、距離、平均ペース、測定開始・一時停止・再開・終了、地図、運動前後のROF-J。
- **必須の動作**：位置情報の許可／拒否、GPS受信不能、機内モード、屋外復帰、画面遷移と復帰、保存二重実行防止、時間/距離の連続性を先に契約化する。
- **実装順**：既存 `runload-app` の測定状態機械・GPS運用を監査 → UI再現 → 状態接続 → 実機GPSテスト → 実データ保存・科学計算連携。
- v2で現在無効化している測定開始を**見た目だけで有効化しない**。実GPS測定を動かす工程まで、誤解を招く架空の距離や軌跡を出さない。

## 共通のUI検証と画像の扱い

イメージ画像は構成比較の参考に使用し、画面の完成判定は実ブラウザのスクリーンショットと操作テストで行う。
画像生成サービスのイラスト・写真は正式な配信素材に採用しない。正式素材が必要なら、開発者の制作物か、出典とライセンスの確認が済んだ素材を使用する。
