# RunLoad v2 — 旧版記録項目の再配置と移植ステータス

更新: 2026-10-24。対象リポジトリ `runload-app-v2`。旧科学アプリ `runload-app` の `main` とCurrentには手を加えない。

## 基準にした旧版コード

- `runload-app/screens/recordInputScreen.js`: 基本情報、ROF-J、コース・走行条件、比較情報、身体・シューズ・メモという4段階。保存コース、歩数の取得元、ラン/ウォーク、気温などの存在を確認。
- `runload-app/screens/mobile/courseEditorScreen.js`: 坂（不明／ほぼ平坦／簡単な割合／区間）、路面（不明／単一／複数割合）、最大5区間。
- `runload-app/ui/rofJPresentation.js` / `core/rofJAuthorConfirmedScale.js`: 旧版の原図5点と責任著者確認済み尺度位置。

## v2の入力画面：今回実装

| 階層 | 項目 | v2の現状 |
|---|---|---|
| 1. 基本 | 走行／休養、日付、距離・時間 | 入力可能。入力途中の変更でも保持。旧版の正式記録種別は走行・休養であり、v2独自の自転車などの選択肢は撤回 |
| 1. ROF-J | 運動前・後を個別に0〜10整数で選択。既存の5枚の原図を尺度目安として表示 | 入力可能。画像は旧公開リポジトリのものを参照。未入力と0を区別 |
| 2. コース・走行条件 | コース名、坂「不明／平坦／割合／最大5区間」、路面「不明／単一／複数割合」、傾斜、路面の種類 | 折りたたみ詳細入力。割合合計・範囲の入力整合性を確認 |
| 3. 比較情報 | 歩数、歩数の取得方法「不明／端末・時計／推定・手入力」、走り方「不明／連続／走歩混在」、走行区間だけの距離と時間、気温、環境メモ | 折りたたみ詳細入力。歩数は自動推定しない |
| 4. 振り返り | 身体の気づき、シューズ名、自由メモ | 折りたたみ詳細入力。ROF-J・身体部位の文献参考値とは別に扱う |

入力はブラウザで現在開いている画面のUI状態としてのみ保持され、「入力内容を確認する」ダイアログで点検できる。**正式な走行保存、科学計算、GPS、過去記録・コースライブラリとの連携は未実装。** 既存の記録・科学情報を書き換えていない。

## 旧版から未移植・統合要件

- **保存コース一覧／最近の3件選択／コース作成・編集後の自動復帰／GPXインポート**：画面上の部分的なコース情報入力とは異なる。専用画面の改修と保存リポジトリ連携が必要。
- **区間・走歩混在の正式モデルバリデーション**：フォーム上の下限・割合の表示確認は今回のUI検証のみ。旧版 `recordInputInteractions.js` と科学計算の入力契約を接続するまで計算結果には反映しない。
- **部位別身体記録の詳細UI、使用シューズライブラリ、保存した記録の改訂**：自由記述と入力欄を先行配置した。旧版と同等の意味・履歴付きデータ構造は後の作業。
- **ROF-J保存ライフサイクル**：現時点の値をセッション中のUI入力として表示するのみ。運動前の入力から測定、運動後の入力、欠測、正式保存までの旧版契約と再検証が必要。
- **正式なコンディション総合スコア**：採用しない。ホームは本人が記録した情報を表示する方向とし、健康状態などを数値的に推測して「良好」と判断しない。

## 表示・検証ルール

- 多数の項目を最初から押しつけない。主要情報とROF-Jを表示し、2〜4の補助項目は展開して編集可能にする。
- 任意項目は空欄のまま保持し、欠測を0に置き換えない。
- 科学的指標・医療診断・路面による部位別係数を新設しない。
- 初回の画像付き比較は実Chromiumの320/390/430/1440pxスクリーンショットから作成する。
- 次の工程は旧版のコースライブラリ・身体部位記録・ROF-J保存状態機械の照合を優先し、UIの入力値を正式な保存・計算へ接続する。
