# ROF-J 結果画面「前後差」欄の表示整理（2026-11-02）

## 対象・問題
- 結果画面・疲労感タブ。画面例では運動前3、運動後8が表示されながら、前後差は「—」となっていた。
- 従来は値が存在しても前後差欄を「—」に固定する仕様。原因は計算エラーではなく、本人申告の時間的順序を客観的に検証できない状態で「運動による変化」を断定しない設計判断。
- 一方、「前後差」という見出しと「—」の併存は、計算失敗・欠測と誤解されうるため、既存3タブを維持する最小の表示整理を行う。

## 機能設計根拠（データ・解釈）
- ROF-J 0〜10は本人申告による疲労感。「運動前」「運動後」は回答区分である。二値の算術差だけから運動を原因とする時間的変化を確認したことにはならない。
- 回答入力操作時刻、本人申告の評価日時、運動開始・終了時刻、訂正履歴は保存しつつ、時間的順序が客観的に実証された情報とは扱わない。
- 前後差計算・推定は追加しない。0は有効な回答で、未回答「—」と区別する。医学的な身体負荷や変化を実測したものではない。

## 画面設計根拠（情報提示）
- 「前後差　—」欄を削除し、運動前・運動後の2値と棒表示に集中させる。前後差専用CSSも標準・モバイルから除去。
- 主説明は「運動前・運動後として記録された疲労感です。実際の評価時刻の前後関係は確認していないため、運動による変化とは断定できません。未回答は『—』で、0と区別します。」とする。
- 既存の詳細開閉「判断できないこと・回答時刻の扱い」、回答時刻・訂正履歴の確認／訂正、結果画面3タブ（身体／疲労感／過去と比較）は維持。
- 画面コード・CSSの両版（独立CSS・Shadow DOMのインラインCSS）を同じ方針で修正する。

## 正常系・反例・検証契約
- 正常系：運動前3／後8は各回答をそのまま表示。差を表示しない。
- 反例1：運動前0は「0」と表示し、未回答「—」と混同しない（null合体演算子を維持）。
- 反例2：片側未回答でも値を0に置換せず、表示上「—」とする。
- 反例3：本人申告の評価時刻が記録されても、時間的変化や因果の断定を追加しない。
- 回帰テスト：`tests/resultExperience.test.mjs` を新しい表示契約に更新（旧欄不存在／旧CSS不存在／2値保持／0と未回答の区別／説明の整合）。既存の3タブおよび科学的適用条件を維持するテストは継続。
- CIおよび実機確認の実施結果は別途確認する。コードの文字列確認のみを実機動作保証とは扱わない。

## 範囲と限界
- 変更対象：`ui/resultExperience.js`、`ui/resultExperience.css`、`ui/resultInlineStyles.js`、`tests/resultExperience.test.mjs`、本記録。
- 変更しない：ROF-J尺度・記録保存形式・訂正履歴・GPS・文献参考値の計算・結果画面の3タブ構成。
- 本変更は情報提示の合理性を高める設計判断。利用者の自己理解向上を実証したものではない。
- 正式なCurrentファイルは上書きしない。後日の統合候補として機能設計根拠と画面設計根拠を分けて保存する。
