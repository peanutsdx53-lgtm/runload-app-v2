# RunLoad｜記録内容確認（S09）・手入力任意アイコンの調整（2026-11-01）

## 観察と課題
利用者のiPhone画面から、日付下の必須3項目の状態チップと距離カードが密接して見えること、入力が有効な場合にも「入力内容を確認しました」と長文の二重説明が表示されること、手入力の任意項目が文字記号で確認画面のSVGと異なることを確認。

## 機能設計根拠
- 必須3項目（距離・時間・活動種目）の状態表示は維持。「入力済み」「要入力」の出し分けは既存の checkManualRequiredFields が担う。エラーと保存可否は checkRecordDraft と既存の保存ボタン制御に委譲し、DOMレイアウト変更が判定へ影響しない。
- 正常な下書きの「入力内容を確認しました」カードを削除。エラー時は内容別の明示的警告と無効化、警告だけある場合は警告表示を残す。未入力・0・不正入力と正常入力を混同しない。
- SVG図柄を新規の表示専用 `ui/recordIcons.js` に集約し、手入力の任意リンクと確認画面が同じ図柄を参照。画面遷移・保存形式・文献参考値の計算を変更しない。
- 保存セクションでは端末内の保持と、12部位の文献参考値には適用条件があることを短く残す。計測や医学的診断の主張に置き換えない。

## 画面設計根拠
- 日付の下の状態チップと距離カードの間に23〜24pxの余白を確保。モバイル320/390・PC1440pxを想定し、3チップの折返しと余白を検証する。
- 有効入力の正常画面は基本情報→詳細情報→保存を直接確認できる構成。未入力時の警告だけを必要時に表示。
- 文字の記号アイコンから、確認画面と共通の5種類のSVGに統一。閲覧画面のSVGをそのまま使い、記録の内容を表す意味に変更なし。

## 確認する正常系・反例
手入力必須がすべて満たされた状態／距離未入力／活動種目未選択／休養日／GPS不使用。PC・スマホでステータスと距離カードの非干渉、任意リンク5件のSVG一致、保存ボタンの有効・無効、横方向オーバーフローを試験。
既存Currentと研究理論の承認済み部分は変更しない。実機でのタップ・OS文字拡大や利用者効果は別途確認。
