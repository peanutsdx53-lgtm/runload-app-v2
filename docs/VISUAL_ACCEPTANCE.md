# RunLoad v2 — 画像対照の厳格評価・受け入れ基準

最終更新: 2026-10-23

## 対照資料
- 参照画像: この会話で制作したPC/スマホ全体構成、結果画面、探究ツリーの採用候補
- 実画面: GitHub Actions `UI browser visual smoke` の実Chromiumスクリーンショット
- 画面幅: PC 1440×900、スマホ 390×844、狭幅 320×740
- **参照画像は製品仕様書ではない**。部位名称やROF-J単位・数値、実測していない身体機能レーダー、GPS地図の架空表示は採用しない。

## 合否の扱い
「ブラウザテスト成功」と「画像に対する見た目の完全一致」は別の判定。自動操作PASSであっても、レイアウト・視覚的完成度が不十分なら「完成」にはしない。

| 評価対象 | 現在の状態 | 修正・検証が必要な点 |
|---|---|---|
| PCの結果 | **構成は前進／最終承認前** | 参考画像にあるカード密度・小さな部位サムネイル・表記を実データ契約に合わせて調整 |
| スマホの結果 | **構成は前進／最終承認前** | 最初の画面に3人体図と数値の一部が自然に収まること。12部位の選択負担を実機で確認 |
| PCの探究ツリー | **枝と28テーマを実装／最終承認前** | 一部の枝ラベルの密集・可読性、空間配置、選択時の見え方 |
| スマホの探究ツリー | **7分野の枝と選択を実装／最終承認前** | 詳細展開の情報密度、枝の変化・成長の表現、シート操作。現行は画像の下部シートと完全一致しない |
| ホーム・記録・履歴・設定 | **製品形式へ刷新／最終承認前** | 各画面の入力・保存・比較等の機能連携、描画精度、情報過多・不足の評価 |
| 測定・コース・シミュレーション等 | **構成作成／最終承認前** | 未接続の操作がある。科学計算とGPSを偽装せず接続後に最終検証 |
| 製品画面中の「デモ」「試作」等の余計な表示 | **除去** | 他画面・PWA案内の新文言も継続監査 |
| 12部位正式ID・前/後/足裏SVG | **維持** | 実科学エンジンとの接続は別工程 |
| 既存6軸レーダー | **補助表示維持** | 架空の筋力/柔軟性/安定性スコアを混ぜない |
| インストール済みWebアプリの更新 | **SWをネットワーク優先へ変更** | iOS実機のオフライン・更新確認は未完了 |
| PC/390px/320pxの横はみ出し | **継続テスト対象** | 付属画面も含め全ルートで検証する |
| 全画面の見た目が生成画像を完全再現 | **未達** | 事実と科学的根拠を守ったデザイン調整および利用者の承認が必要 |

## リリース前の必須条件
- PC/スマホの主要6領域と実在する付属画面を、実ブラウザのスクリーンショットで個別に確認する。
- 320/390/1440でスクロールやタッチ対象に問題がない。
- 12部位の位置・名称・数値、Reference-100、ROF-J、GPSの有無、欠測と0、比較適格性、休養と走行、安全分岐を正しく表現する。
- 探究ツリーのカテゴリとテーマ、今回の記録に関連する光、本人の問いの扱いに意味上の矛盾がない。
- 生理的能力や筋の「使用量」を根拠なしに数値化しない。
- 不要な独立画面を統合する際には、各機能の移行先を確認し、削除で損なわれる機能を残さない。
- 見た目の自動テストに加え、実機での使いやすさと視覚品質の承認を得る。

## 運用
- 新UIのみ `runload-app-v2/main` で作業し、旧 `runload-app/main` とCurrentは変更しない。
- **AI画像生成サービスの出力は製品の素材として取り込まない**。過去の画面イメージは情報配置の参考に留め、固有の装飾を画像から直接トレースしない。
- 現在の枝・葉・背景はオリジナルなコード図形による暫定UI表現。アプリアイコンは暫定素材。外部素材を使う場合は `assets/ASSET_REGISTER.md` のライセンス確認・来歴登録を必須とする。
- 実ブラウザで撮影したスクリーンショットだけを、UI改修の達成度の根拠とする。
- 完璧または完成を宣言する際は、具体的な合格条件と証拠を示す。
