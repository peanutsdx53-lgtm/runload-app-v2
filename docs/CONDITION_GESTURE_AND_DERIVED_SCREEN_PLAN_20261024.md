# RunLoad v2 — コンディションUI修正・長押し操作・記録派生画面設計（2026-10-24）

## 事実と今回の修正（main）
- ユーザーのiPhone実機スクリーンショットおよび画面録画で、ホームの「コンディション」モーダルの日付欄が右端にあふれ、白いフォームが記録画面の色調と異なり、睡眠履歴のない大きな空グラフが表示されることを確認。
- `ui/homeExperience.js`: 日付をラベル横並びのコンパクト行にし、未記録時の睡眠0時間を初期値として見せない。睡眠履歴がないときは「睡眠の記録はまだありません」を出す。
- `ui/homeExperience.css`: .hx-dialog の幅、内部グリッド、日付入力の幅を画面幅で拘束。フォームは記録画面と共通する紺色・青緑の境界線・16px以上の入力文字へ。モーダルの内部縦スクロールと背景のスクロール禁止を分離。狭いスマホも対象。
- `app.js`: モーダル開閉に従い body.runload-dialog-open を切替。既存の入力保存・削除・プレビューデータは改変しない。
- `ui/homeDashboardDrag.js`: ウィジェット編集用ハンドルのタッチポインターを捕捉。長押し後の指移動に伴う**意図しない画面自動スクロール**を止める。通常のページスクロールと、モーダル内の必要な縦スクロールは維持。対象はホームダッシュボード編集のドラッグのみ（アプリの全長押しを無効化したわけではない）。
- `tests/browserSmoke.mjs`: モーダルの日付入力が内側に収まること、横スクロールが発生しないこと、暗色フォーム、背景ロックの開閉、ハンドルのtouch-action:noneを確認。

## 現行実装から変更していないもの
- 正式GPS測定エンジン、正式走行保存、ROF-Jの意味・尺度、比較値計算、記録データの互換性。
- 実績はホームカード＋詳細表示のみ。正式な実績判定エンジンとの接続は引き続き未実装。
- コンディションは端末内の任意入力。OS依存のヘルスケア連携・端末間同期は未実装。

## 次の画面案（**提案段階であり未承認・未実装**）
- GPS測定（スマホ専用）: 準備／測定中／一時停止／終了確認。時間を主指標、距離・ペースを副指標とし、GPS状態を常時明示。誤終了を防ぐ二段階確認。軌跡は本物のGPS保存データがある場合のみ表示し、心拍等は未接続なら表示しない。
- 測定後の確認: 計測で得た時間・距離を編集確認し、ROF-J・コース・環境・身体など共通入力を必要に応じて追加。正式保存のコードは未接続なので有効化しない。
- ROF-J: 運動前・運動後を別状態、数値0〜10は既存承認尺度の説明に従い選択。コンディションの日常生活とは別。
- 歩数・走り方: 歩数と取得方法の選択、走歩混在の時だけ距離・時間の詳細を展開。
- 環境: 気温・環境メモを任意で登録。不明を0とみなさない。
- 身体・使用品: 自覚メモと旧版の部位別入力・シューズ選択を分ける。旧保存契約未接続のまま新しい本番データを捏造しない。
- 派生画面はPC・スマートフォン共通。ホーム/記録と共通の背景・入力欄・16px文字・タップ領域。入力途中で戻っても値を失わない。将来的な探究ツリー連携はデータ意味を保ったうえで実施。
