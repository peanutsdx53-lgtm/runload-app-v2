# RunLoad v2 — GPS測定画面 UI実装と設計引継ぎ（2026-10-24）

## 対象
`peanutsdx53-lgtm/runload-app-v2` の `#/measurement`。旧 `runload-app` は変更していない。参照画面はライブラリの `RunLoad_v2_GPS測定_4状態デザインVer2_20261024.png` と、同HTML試作。

## 実装した部分
- `ui/measurementExperience.js`: 準備、測定中（表示例）、一時停止（表示例）、終了確認（表示例）の4状態と操作遷移。
- `ui/measurementExperience.css`: ホームと同じ濃紺・青緑・立体カード。PCは計測情報と補助説明の2カラム、スマホは1カラム。320px・390px・430px・1440px対応。
- `app.js`: `#/measurement` を旧白背景のプレースホルダーから置換。記録方法選択画面からの導線を維持。表示例の操作はURL・正式保存・位置情報を変更しない。
- `index.html`, `sw.js`: 追加したJS/CSSを読込・PWA事前キャッシュ。
- `tests/measurementExperience.test.mjs`, `tests/browserSmoke.mjs`, `.github/workflows/ui-smoke.yml`: 無許可の計測開始防止、プレビュー遷移、2段階終了、画面サイズ・スクロール・ナビ色の検証を追加。

## 画面上の情報と安全な扱い
- `準備`: 経過時間は `00:00:00`、距離・ペースは `—`、GPS状態は `GPS未接続`。**測定開始ボタンは無効**。現在のv2では位置権限要求、計測、走行保存をしない。
- `表示例を見る`: 明示的に選択したときだけ、32分16秒・5.21km・6:12/kmのサンプル画面を表示。すべて表示例と明記。
- `測定中（表示例）→一時停止（表示例）→終了確認`: 表示上の操作だけ。GPSイベント、タイマー、ストレージ書込を伴わない。
- `終了` は確認ダイアログを経る。`測定画面へ戻る` と `表示例を終了` を区別。戻った状態は実際の測定状態ではない。
- 地図に架空の経路を描かない。位置データがない場合は空表示。

## 既存の科学計算・保存との関係
- GPSセンサー、ROF-J本体、12部位比較値、走行記録の正式保存、コースライブラリの計算や記録は変更していない。
- 旧RunLoadの測定画面に存在した「自由／時間／距離」モード、時間・距離目標、測定前後ROF-J、計測結果の手入力引継ぎ、GPS精度低下、バックグラウンド復帰、軌跡保存などは**本番GPS接続時の明示的な要件**として残す。今回それらを実装したとは扱わない。
- 本番GPS実装時は、エンジンから取得した正式状態を一方向で画面に反映する必要がある。今回のプレビュー遷移を流用して「計測機能を実装した」と判定してはならない。

## デザイン・UXの残課題
- iPhone/Androidで実機操作を確認すること。Chromiumのスクリーンショットとタッチテストは、OSのGPS権限やバックグラウンド挙動を証明しない。
- 実測計測のUIはGPS状態・権限・経過時間・距離・平均ペース・一時停止・終了確認が中心。計測中の下部ナビは非表示候補。
- 次の設計はGPS測定前の「測定条件」と、正式データ連携時の「測定終了後の記録確認」、およびROF-J等の派生画面。データ形式を増やさず共通記録入力へ引き継ぐ方針。
