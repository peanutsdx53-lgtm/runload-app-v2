# S07 任意画面｜身体・使用品とコース・走行条件の調整（2026-11-01）

## 実機フィードバックと課題
- 身体・使用品（S07）のモバイル底部ナビだけ明るく表示され、手入力や他の任意入力画面と色が揃っていなかった。
- コース・走行条件（S08）の「使わない場合は次へ進めます」「この名前は保存コースの識別用です。走行距離・時間は含みません。」は、画面操作に寄与しない重複説明。
- 03の「1→2」は操作順序を誤認させる。実際、記録への適用ボタンは入力画面に戻り、コース保存を自動実行しない。逆にコースを保存しただけでは記録は保存されない。
- 保存後の更新／別名保存ボタンが下方のみであり、保存コースを読み込んだ場合の後続操作が見つけにくい。

## 機能設計判断
- コースのロード・更新・別名保存・削除は既存のcoursePresetStore契約を維持。記録への適用は既存のdata-rv-apply経路を維持。二つを依存ステップに変更しない。
- 保存データの改変なし。コースの名称と坂道・路面のみが対象。距離・時間・ROF-J・身体記録は保存コースに含めない。利用者の現在の記録と過去記録は上書きしない。
- セルフレポート部位図は科学的計算値や傷害リスクの判定に変更しない。

## 画面設計判断
- 重複注意文を取り除き、01のコース名入力を単列化。
- 03は「今回の記録に使う」対「保存コースとして残す」を並列選択として明示。番号1・2を除去する（01/02/03の画面配置番号はナビではなく読み順補助）。
- 01カード内には、現在の選択が実在する保存コースである場合に限り、「保存コースを更新」「別名で保存」の既存アクションも表示。初期状態・無効保存領域ではこの操作を出さない。03の既存アクションは維持。
- モバイル身体・使用品ページの底部ナビを同系ダーク背景／青緑アクティブ表示へ上書き。PC側のサイドバーは既存トーンを維持。
- 画面の補足文を削除したが、保存・適用の意味と確認情報は残し、ユーザーの可逆的操作を妨げない。

## 検証
- node:test の正常系・保存コース選択済み・未選択・概要の区別に対する追加アサーションを設定。
- 既存のcoursePresetStore保存／読込／削除／更新／スナップショット規約は不変更。
- PC幅1440px、スマホ390px/320pxの空・保存済み／入力済み状態のスクリーンショットにより可読性と横スクロールを検証する。
- ブラウザCIとiPhone/Android実機検証は区別する。正式Currentを無断更新しない。
