# RunLoad UI/UX 継続改善: S09・S05・S07（2026-11-01）

## 範囲・変更原則
前回の総合ブラウザCI復旧（main `562c0b84`）を引き継ぎ、機能追加・理論の変更・正式Currentの変更は行わない。対象はS09結果、S05コース入力、S07身体・使用品の**表示と操作理解**。結果は身体・疲労感・過去と比較の3タブ構成を維持。GPS測定後の記録入力画面は本工程で変更しない。

### A：S09 結果画面
- **画面設計根拠**：部位別参考値の比較表示は既に実装されていたため、再実装せず、後続CSSによる `details.rv4-compare-provenance{display:grid}` の競合を除去し、折りたたみ式の「完全な記録ID」表示を保つ。比較見出し、日付ラベル、参考値の差、計算方法と限界の文字を読みやすくする。ROF-J回答時刻・解釈不能の説明も小さい文字を増寸。
- **機能設計根拠**：2件の元記録・部位・再計算方法を変更しない。問いの継続パネルで長大な記録IDを直接露出せず、ID末尾8文字を手掛かりにし、完全なIDは上の開閉パネルで確認可能。保存元と比較元の同一性・適用不能時の非算出は保持。
- **限界**：単一モデルの文献参考値の差であり、本人の組織負荷・損傷リスク・疲労変化を測ったものではない。過去2件の因果効果も評価しない。
- **実装**：`ui/resultInlineStyles.js`, `ui/resultExperience.js`。
- **正常・反例**：適格記録2件の同一部位比較・日付/完全ID開閉、異種活動・範囲外速度・不明な比較ID・0点/未回答の区別を既存ブラウザシナリオで評価。CSS表示と文字サイズの新規アサーションを追加。

### B：S05 コース・走行条件
- **画面設計根拠**：最大5区間の4項目入力が縦長のため、区間別割合を見出しに示し、入力済み件数・入力分の合計を即時表示する。PCは4カラム、スマホは2カラムにして走査と編集を支援。区間削除のタップ領域を44px以上にする。
- **機能設計根拠**：「未入力」と入力値0を区別し、入力済みの割合が100%でも区間が未入力なら完了表示しない。負値・上限超過・NaNは不正値として表示。進捗は保存値ではなく既存の入力内容から導出する表示情報のみ。`input`イベントで再描画せず更新し、IME/キーボードフォーカスを維持する。確定時の従来の`courseReadiness`判定を変更しない。
- **限界**：割合は利用者申告のコース構成。GPS実測/勾配や路面影響の定量モデルではない。
- **実装**：`ui/recordExperience.js`, `ui/recordExperience.css`, `app.js`。
- **正常・反例**：0区間・0%入力と未入力・40/60%・2/5入力で合計100%だが未完成・5区間上限・範囲外120%・リアルタイム更新・フィールドフォーカスをテスト追加。

### C：S07 身体・使用品
- **画面設計根拠**：画面上の部位選択（作業中のUI状態）と記録する本人の文章は別。部位名を文章に追加する操作を案内し、反映後は二重追加ボタンを無効化する。文献上の限界、選択チップを読みやすくし、スマホのタブ・部位選択・解除の操作領域を最低44pxに拡大。
- **機能設計根拠**：12部位の公式名称・SVG形状・既存の3面切り替え・自由記述上限500文字、使用品100文字を保持。選択を自動保存したり、部位選択から診断を推測したりしない。同じ部位名の自動二重挿入、変更後の部位名を新しい行として無断追記することを避け、利用者に本文の直接編集を案内する。
- **限界**：本人の自覚情報であり医学的診断ではない。画面内のUI選択は、文章に追加しない限り端末保存済み記録の項目と見なさない。
- **実装**：`ui/bodyContextExperience.js`, `ui/bodyContextExperience.css`。
- **追加の副作用監査**：利用者が転記済みの部位名を自覚情報本文から削除・修正するとき、本文入力中のフォーカスを失わせず、転記ボタンを直ちに再有効化・無効化して案内を同期する（`app.js`の入力処理、`transferStatus`を共有）。
- **正常・反例**：選択のみ・文章へ追加・再追加無効・選択後変更時の二重行防止・12部位選択時の3件/残り9件の開閉をテスト。CSSの説明文字サイズと操作領域をブラウザ検査。
