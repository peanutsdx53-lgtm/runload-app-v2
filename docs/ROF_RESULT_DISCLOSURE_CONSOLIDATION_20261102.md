# 疲労感結果表示：説明・時刻・訂正履歴を一つに整理（2026-11-02）

## 現行画面の問題
結果画面「疲労感」に、(1) 大きい説明、(2)「判断できないこと・回答時刻の扱い」、(3)「回答時刻と訂正履歴を確認・訂正」の3領域が縦に並び、主観値の解釈限界を重複して伝えていた。ユーザーの実機画面で、説明の長さと情報密度が確認された。

## 機能設計根拠（変更なし）
- ROF-J（0〜10）は本人申告の疲労感。運動前／後は回答区分であり、時間的な前後関係、運動を原因とする変化、測定された生体負荷を示さない。
- 入力操作時刻と本人申告の評価時刻は異なる性質の情報で、どちらも運動との実際の時間的順序の客観的保証ではない。数値の前後差は追加しない。
- 0は有効回答、未回答は「—」。記録された時刻、運動時刻、訂正履歴と訂正処理の保持が必要。保存済みの手入力にのみ訂正操作を提示する。

## 画面設計根拠・差分
- 常時表示：運動前／運動後の二値と棒、短い注意文「本人が記録した疲労感です。運動による変化とは断定できません。」を残す。
- 旧来の独立した「判断できないこと・回答時刻の扱い」を廃止。判定根拠、入力時刻、評価時刻、過去の訂正、訂正フォームを **一つの折りたたみ領域**に集約する。
- 保存済みで訂正可能：「回答時刻・訂正履歴を確認・訂正」。未保存やGPS：「回答時刻と判定の限界を確認」。操作できる場合とできない場合を区別する。
- 詳細内に「未回答は『—』、0は有効値」、本人申告の時刻の限界を明記。元から長い訂正履歴リストのみ詳細内で二段階目の開閉を維持する。
- `rv4-fatigue-note` を簡潔にして高さを縮小。時刻・訂正履歴セクションの見出し階層を修正し、入れ子の枠と余白を調整。Shadow DOM内CSSと対応する独立CSSの双方を更新する。
- 身体／疲労感／過去と比較の3タブ構成は維持。記録保存・ROF-J入力・科学的文献参考値の計算・GPS経路を変更しない。

## 正常系・反例
1. 運動前3、運動後8：両方を表示し、前後差や運動起因の変化量を新たに表示しない。
2. 運動前0、運動後未回答：0と「—」を区別する。
3. 保存済み手入力で回答時刻あり：一つの開閉欄内で、時刻・訂正履歴・訂正操作にアクセスできる。履歴は既存どおり保持。
4. GPSの本人申告：判定上の限界と入力操作時刻は確認可能。手入力記録専用の訂正フォームは提示しない。
5. 時刻未確認・未入力：時間的な変化を測定したような表現はしない。

## 検証・限界
- 回帰テスト `tests/resultExperience.test.mjs` を新しい表示契約に更新し、1開閉欄、訂正保存操作の存続、GPS表現、2値・3タブの不変、旧独立欄の削除、CSSの整合を確認する。
- GitHub Actionsの結果と端末上での表示は、コミット後の検査結果に従って別途評価する。コード上の整合が確認できても、iPhoneでの最終実機検証を完了とみなさない。
- 本改修は**機能の成立と表示設計の合理性**の範囲であり、初心者の自己理解向上や運動による変化の因果を実証したものではない。
